# Managed asset contract

- Admin is the business write boundary. COS is Primary; R2 is a best-effort Mirror. Validate and upload/verify Primary before touching business references. Mirror failure returns a warning and never blocks a successful Primary publication.
- Game Showcase Campaign artwork extends that same pipeline in GFG: `showcase-desktop` is AVIF exactly 1600×800, `showcase-mobile` exactly 1200×675, each at most 5 MiB. Keys are `game/showcase/{campaign_id}/{desktop|mobile}/{hash32}.avif`. Primary-item AVIF spatial metadata is checked on the server; bytes are never resized, cropped, rotated, converted or recompressed. Desktop is required for publication, mobile is optional. The existing CloudOps key allow-list, inspector and mirror repair support both kinds. Clearing removes only the Campaign reference, and cannot invalidate a published Campaign. See [Showcase](../docs/game-showcase.md).
- Object keys are provider-neutral and content-addressed by the first 32 lowercase hexadecimal characters of SHA-256: `nav/sites/{id}/icon/{hash}[.{ext}]`, `nav/hero/{desktop|mobile}/{hash}.avif`. The full hash and asset kind are object metadata. Native COS uses `x-cos-meta-*`; the R2 S3 API uses `x-amz-meta-*`. Adapters expose the same metadata contract.
- Content-addressed objects carry `public, max-age=31536000, immutable`. Re-uploading identical content is idempotent; a conflicting existing Primary is an error. No public or Admin object-delete API exists. Failed DB transactions and replaced references leave orphan objects for later maintenance, never compensating deletes.
- Site icons retain their original bytes and optional lowercase extension, up to 2 MiB. Desktop and mobile Hero are independent AVIF-only pools (5 MiB maximum), with no resize, pairing, or cross-pool fallback. Local Hero images retain their existing original-byte and browser-storage contract.
- Business sources of truth are `gfn_site.icon` and `gfn_home_hero_asset`. No generic asset/replica/job/version registry is permitted. Nav business SQL uses Goose/sqlc; audit follows the existing separate GFN/GFA transaction boundary.
- Public APIs return object keys. Nav Web separates the saved Auto/Primary/Mirror mode from its 12-hour recommendation cookie. Each resource snapshots its provider when mounted or its key changes; probes and saved preferences never change an existing resource URL. Two background GET probe rounds consume and verify the fixed 8192-byte `system/probes/cdn.bin`; they never block SSR. Real load failures try the other CDN and mark diagnostics stale without changing the saved mode. Final fallback is the bundled icon, or no Hero image.
- Hero source preferences are SSR-readable cookies containing Random/Fixed/Local mode and independent desktop/mobile string IDs, never object keys. Fixed IDs resolve current eligible rows at request time, with same-viewport random fallback. Local SSR exposes no cloud Hero URL, and old local storage cannot override explicit Random/Fixed. The public Hero catalog is paginated metadata with direct selected-ID lookup; only a visible current preview loads image bytes. Explicit Hero selection Save retains the old frame until its replacement renderer loads; only the real `picture`/`img` owns CDN fallback, and unchanged viewport resources retain their route snapshots. See `docs/managed-assets.md` for migration and Save/Cancel semantics.
- Bundled branding, platform icons, tool covers, avatars, default logo/static page texture and error artwork live in Nav Web public assets. Steam has an independent Auto/China/Global routing manager, SSR-readable mode/recommendation cookies and per-resource candidate snapshots. Its two logical groups retain within-group and cross-group fallback. See `docs/managed-assets.md` for probe and preference semantics.
- Public page decoration (#149/#151) is CSS radial dots in `PublicPageBackground.vue`, fixed behind content and fading through nested linear masks; the opaque Home Hero covers the dots. CSS tokens own the fixed canvas, dot geometry/color/alpha; no image, browser preference, IndexedDB or catalog API participates. Home Hero local images remain independent.
- `gfn_background_pattern` and immutable historical pattern objects are retained without migration or data writes. Catalog business routes, queries, uploads and editors are retired. CloudOps may still inspect/repair existing `nav/patterns/{hash}.svg` objects using its unchanged bounded key allow-list; this does not re-enable catalog publication.
- Storage and CloudOps secrets belong only in explicit Admin YAML. Root `.env` is a private developer input, never an application runtime dependency. CloudOps is scoped to configured hosts and uses capabilities; zone-wide EdgeOne purge has its own Owner-only capability and endpoint.
- The initial production migration used a one-time maintenance cutover with pre-uploaded objects, a manifest, DB backup, schema migration and explicit cutover/rollback SQL; it completed on 2026-09-14. Daily Managed Assets operations use Admin. Do not rerun initial `cutover.sql` against the already-migrated production database. Goose never contacts object storage. No permanent legacy-prefix or dual-field compatibility layer is retained. See the [production acceptance record](../docs/acceptance/v3-alpha8-managed-assets-production-acceptance.md) and [historical cutover runbook](../docs/managed-assets-cutover.md).

Admin serves `Cross-Origin-Embedder-Policy: unsafe-none` so normal public CDN image previews work without requiring CORP headers. Public asset domains still allow the frontend origin for CDN probes. Site Icon SVG remains an image URL, never inline page markup.
