# Managed asset contract

- Admin is the business write boundary. COS is Primary; R2 is a best-effort Mirror. Validate and upload/verify Primary before touching business references. Mirror failure returns a warning and never blocks a successful Primary publication.
- Object keys are provider-neutral and content-addressed by the first 32 lowercase hexadecimal characters of SHA-256: `nav/sites/{id}/icon/{hash}[.{ext}]`, `nav/hero/{desktop|mobile}/{hash}.avif`, and `nav/patterns/{hash}.svg`. The full hash and asset kind are object metadata. Native COS uses `x-cos-meta-*`; the R2 S3 API uses `x-amz-meta-*`. Adapters expose the same metadata contract.
- Content-addressed objects carry `public, max-age=31536000, immutable`. Re-uploading identical content is idempotent; a conflicting existing Primary is an error. No public or Admin object-delete API exists. Failed DB transactions and replaced references leave orphan objects for later maintenance, never compensating deletes.
- Site icons retain their original bytes and optional lowercase extension, up to 2 MiB. Desktop and mobile Hero are independent AVIF-only pools (5 MiB maximum), with no resize, pairing, or cross-pool fallback. Server patterns accept SVG files up to the common 5 MiB upload limit. SVG content is preserved without parsing, sanitizing, or element/attribute restrictions. Local backgrounds likewise preserve original SVG bytes within their common 10 MiB file limit.
- Business sources of truth are `gfn_site.icon`, `gfn_home_hero_asset`, and `gfn_background_pattern`. No generic asset/replica/job/version registry is permitted. Nav business SQL uses Goose/sqlc; audit follows the existing separate GFN/GFA transaction boundary.
- Public APIs return object keys. Nav Web resolves Primary/Mirror using a 12-hour cookie preference, initially Primary. Two rounds of background GET probes consume and verify the fixed 8192-byte `system/probes/cdn.bin`; they never block SSR. Runtime failures try the other CDN and invalidate preference. Final fallback is the bundled icon/pattern, or no Hero image.
- Bundled branding, platform icons, tool covers, avatars, default logo/pattern and error artwork live in Nav Web public assets. Steam CDN behavior is independent and unchanged.
- User-local backgrounds never upload: IndexedDB stores the Blob, localStorage stores source and explicit overrides. Server preferences retain the pattern ID, not a copy of server defaults. Missing or disabled patterns fall back to the bundled default.
- Storage and CloudOps secrets belong only in explicit Admin YAML. Root `.env` is a private developer input, never an application runtime dependency. CloudOps is scoped to configured hosts and uses capabilities; zone-wide EdgeOne purge has its own Owner-only capability and endpoint.
- Production uses a short maintenance cutover with pre-uploaded objects, a manifest, DB backup, schema migration and explicit cutover/rollback SQL. Goose never contacts object storage. No permanent legacy-prefix or dual-field compatibility layer is retained.

Admin serves `Cross-Origin-Embedder-Policy: unsafe-none` so normal public CDN image previews work without requiring CORP headers. Pattern CSS masks still use standard browser CORS; public asset domains must allow the frontend origin. SVG is rendered through image URLs/CSS masks, never injected as inline page markup.
